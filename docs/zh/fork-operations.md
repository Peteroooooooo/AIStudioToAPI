# 独立版运维说明

本分支基于 v1.3.5 源码，包含 `FormatConverter.js` 补丁。镜像由本仓库构建，仅发布 `linux/arm64` 到 `ghcr.io/peteroooooooo/aistudio-to-api`，使用 Docker v2 镜像清单格式兼容 Docker 20.10。部署时使用版本标签或完整提交 SHA 标签，避免依赖 `latest`。

## 账号健康规则

| 回包            | 自动处理                                                  |
| --------------- | --------------------------------------------------------- |
| 429             | 当前账号立即冷却 5 分钟；再次发生时逐级增加，最多 40 分钟 |
| 401             | 10 分钟内两个不同请求均失败后标记为“需重新登录”           |
| 502/503/504     | 10 分钟内连续三次失败后冷却，从 1 分钟起逐级增加          |
| 400/403/404/422 | 直接返回给调用方，不禁用账号，不重复尝试                  |

账号状态保存在 `/app/data/account-health.json`，不会修改认证 cookie。控制台账户列表可手动停用、启用或重置健康状态。冷却结束后账号自动重新参与轮换；“需重新登录”和手动停用必须由管理员重置。后台会在隔离账户后重新平衡浏览器上下文，正在处理请求的上下文会延后关闭。

`/health` 是进程存活检查，始终保留原有语义。`/health/ready` 仅在当前账号健康且 WebSocket 已连接时返回 200，否则返回 503。调用端在所有账号不可用时会收到明确的 503。

## 部署与回滚

浏览器上下文是主要内存来源。先按主机内存预算设置 `MAX_CONTEXTS`，并通过容器环境核对实际值；观察内存与账号切换延迟后再调整。清理 Linux 文件缓存不会减少浏览器常驻内存。

切换前保存现用镜像的标签或 digest、Compose 配置，以及认证和数据目录的备份。认证文件应单独保管，不要打包进镜像或提交到仓库。

先在隔离环境验证新镜像及 `/health/ready`。单机替换容器会有短暂连接中断，应在允许切换的时间窗口修改 Compose 的镜像标签和 `MAX_CONTEXTS`，然后重新创建容器。验证 API 格式、工具调用、429 冷却、管理界面和内存。回滚时恢复先前的镜像与 Compose 配置。

推送 `stable` 或版本标签会运行测试、JS lint 和前端构建；只有版本标签会构建 arm64 镜像，并同时发布版本标签和完整提交 SHA 标签。部署时建议记录镜像 digest 以固定实际内容。镜像必须构建完成后才能部署；首次发布还需确认 GHCR 包的可见性及目标主机的拉取权限。
