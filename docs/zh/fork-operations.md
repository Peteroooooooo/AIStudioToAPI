# 独立版运维说明

本分支从正在使用的 v1.3.5 源码开始，包含 Cubie 容器中已验证的 `FormatConverter.js` 补丁。镜像由本仓库构建，仅发布 `linux/arm64` 到 `ghcr.io/peteroooooooo/aistudio-to-api`。使用版本标签或完整提交 SHA 标签，避免依赖 `latest`。

## 账号健康规则

| 回包 | 自动处理 |
| --- | --- |
| 429 | 当前账号立即冷却 5 分钟；再次发生时逐级增加，最多 40 分钟 |
| 401 | 10 分钟内两个不同请求均失败后标记为“需重新登录” |
| 502/503/504 | 10 分钟内连续三次失败后冷却，从 1 分钟起逐级增加 |
| 400/403/404/422 | 直接返回给调用方，不禁用账号，不重复尝试 |

账号状态保存在 `/app/data/account-health.json`，不会修改认证 cookie。控制台账户列表可手动停用、启用或重置健康状态。冷却结束后账号自动重新参与轮换；“需重新登录”和手动停用必须由管理员重置。后台会在隔离账户后重新平衡浏览器上下文，正在处理请求的上下文会延后关闭。

`/health` 是进程存活检查，始终保留原有语义。`/health/ready` 仅在当前账号健康且 WebSocket 已连接时返回 200，否则返回 503。调用端在所有账号不可用时会收到明确的 503。

## Cubie 切换计划

2026 年 9 月检查时，Cubie 正在运行的 `aistudio-to-api` 容器约使用 4.36 GiB，运行时 `MAX_CONTEXTS=6`。浏览器上下文是主要内存来源。第一次切换到独立版时建议改为 `MAX_CONTEXTS=2`，观察内存与切换延迟后再决定是否降至 1。不要通过清理 Linux 文件缓存来处理浏览器常驻内存。

当前容器的可写层含有已运行的格式转换补丁。切换前应保存当前 Compose 配置、认证目录、数据目录，并将当前容器保存为回滚镜像，例如 `docker commit --pause=false aistudio-to-api aistudio-to-api:pre-fork`。原始上游 `latest` 镜像本身不包含该补丁。

在其他机器或有足够内存的环境验证新镜像及 `/health/ready`。Cubie 当前内存占用较高，不宜同时启动第二个完整浏览器容器。单机替换容器会有短暂连接中断，因此应在允许切换的时间窗口修改 Compose 的镜像标签和 `MAX_CONTEXTS`，然后重新创建容器。验证 API 格式、工具调用、429 冷却、管理界面和内存。回滚时恢复保存的镜像及原 Compose 配置。

推送 `stable` 或版本标签会先运行测试、JS lint 和前端构建，再构建 arm64 镜像。镜像必须构建完成后才能部署；首次发布还需确认 GHCR 包的可见性及 Cubie 的拉取权限。
