# 账号接单池

运行配置保存在 `data/config.json` 的 `settings` 中，可在管理页面的设置里热更新。

```json
{
  "maxContexts": 4,
  "rateLimitCooldownSeconds": 18000,
  "maxRetries": 3
}
```

上例只展示相关字段，修改时保留已有配置的其他字段。

| 项目       | 原机制                               | 当前机制                                                           |
| ---------- | ------------------------------------ | ------------------------------------------------------------------ |
| 账号上限   | 多账号保持浏览器，主要由当前账号处理 | 最多 N 个健康就绪账号接单，每账号一个执行槽位                      |
| 新对话     | 优先当前账号                         | 优先已有历史缓存（包括待创建），否则按执行与排队数、登记会话数分配 |
| 旧对话     | 缓存匹配与全局轮转共同决定           | 保持原账号；繁忙时限时排队，缓存失效不迁移                         |
| 429        | 短暂退避                             | 自动关闭滑块，默认五小时后开启；期限持久化，手动开关取消旧计划     |
| 不可用账号 | 全局切换                             | 会话迁移到一个新账号；原账号恢复不抢回会话                         |
| 尝试次数   | 部分缓存回退不计数                   | 首次、重试、迁移与缓存回退共用 `maxRetries`，上传只尝试一次        |
| 管理页面   | 当前账号、文字操作                   | 接单数、在途数、排队数；启停开关与三点菜单，自适应布局             |

## 会话与缓存

- 所有客户端共用同一规则，不解析 Agent 私有的用户标识格式。有明确会话 ID 时优先使用：请求头 `x-conversation-id`、`x-thread-id`、`x-session-id`、`conversation-id`、`thread-id`、`session-id`，其次是请求体 `metadata` 中的 `conversation_id`、`thread_id`、`session_id`。同一会话的值应保持稳定，不同会话使用不同值；这些请求头不会转发给 Google。
- 没有明确 ID 时，按同一调用方的完整历史消息前缀推断续聊。单条相同问候和被多个会话共用的前缀不会强行合并；历史被裁剪或改写后无法匹配，显示“未关联”，仍正常生成。用户 ID、请求 ID 和缓存亲和键不作为会话 ID。
- 归属信息持久化为哈希，不保存提示词。登记容量有限，淘汰空闲旧记录；会话不会因跨天、缓存到期或模型/系统/工具配置变化而自动重置。界面编号按首次记录日期生成，旧对话保持原编号。
- Google 显式缓存属于创建账号。有效历史缓存优先复用；缓存创建中、到期或不支持缓存时，仍可使用完整请求继续生成。
- 迁移后只有新归属账号负责创建后续缓存；失效归属的维护任务停止，晚返回的资源清理。
- 冷却秒数是本地策略，不代表已读取 Google 的额度恢复时间。缓存按账号、模型、系统/工具配置和完整内容前缀严格匹配；命中不代表同一会话。复用截止时间取上游到期时间和本地 `cacheTtlSeconds` 的较早值，普通命中不续期；显式续期成功后重新计时，与账号冷却和会话归属分开。
- 请求排队、重试和响应共享本次请求的总超时，同时保留流式分块超时。流式已输出后不自动重放。

## 账号和资源

滑块关闭会立即停止新分配和新的缓存维护，执行中的请求排空。有空余浏览器名额时保留连接好的页面，测试可直接复用；需要给开启的账号让出名额时才回收。繁忙账号删除需要显式强制；强制删除只取消该账号的请求。

- 自动停用：429 按设置安排开启；明确的连接故障或连续三次 502/503/504 暂停一分钟。自动停用原因和时间会显示在关闭状态下。这是本地退避策略，不是 Google 官方额度恢复时间。
- 手动开启：清除旧的自动开启计划。手动关闭：一直关闭，除非再次手动开启。自动停用后不操作则保留原计划，不需要额外按钮。
- 单独测试：固定所选账号发送真实请求。关着的账号也能测，成功或失败都不改变开关或原定开启时间；已开启账号测试遇到新的 429 会自动停用。测试页面受保护，不会被后台调度关闭。
- 主状态只有已开启、处理中、已关闭。连接、运行名额、自动开启时间和错误作为简短备注；过期 Auth 仍需更新，开关开启不等于已验证能生成。

Google File、上传会话和 `cachedContents` 资源必须留在创建账号，无法仅凭资源名称跨账号重放。通过本服务创建的资源会登记归属；未知归属返回 409。拥有这些资源的账号不可用时，客户端应重新上传，或提供可由新账号完整重建的输入。

浏览器池是否真正能长期并行接单，仍取决于各账号 AI Studio 登录和 WebSocket 通道保持有效；页面只将健康且连接就绪的账号计为接单账号。
