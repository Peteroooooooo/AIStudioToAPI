# Codex 多轮重复回答：核查与修复

核查日期：2026-10-05。对应对话：“梳理 tools 调用实现”。

## 已复现的问题

该对话使用 `gemini-3.8-flash`，Codex 的自定义服务配置使用 `wire_api = "responses"`。
本地记录完整保存了用户问题、工具调用及结果、助手答案；助手答案的文本块类型是 `output_text`。

`FormatConverter.translateOpenAIResponseToGoogle()` 原先只读取普通消息中的 `text` 和 `input_text`，
忽略 `output_text`。因此多轮请求中的助手文字被静默删除，用户问题与工具结果仍保留。
使用原对话的记录逐轮重建历史，并送入本地转换器，得到以下结果：

| 下一轮问题                 | 历史助手答案数 | 应保留的助手答复字符 | 修复前保留字符 | 修复后保留字符 |
| -------------------------- | -------------: | -------------------: | -------------: | -------------: |
| 要求举例                   |              1 |                2,002 |              0 |          2,002 |
| 询问能否推广到所有 Web API |              2 |                6,476 |              0 |          6,476 |
| “真的吗”                   |              3 |               12,438 |              0 |         12,438 |

这是本地转换层的确定性复现，未抓取线上服务该次请求的实际 HTTP 请求体。

例如，正确历史应为 `user(A) → model(B) → user(C) → model(D) → user(E)`，
原转换会变成 `user(A) → user(C) → user(E)`。模型看不到之前已经给出的答案，
可能重新回答前面的多个问题。这与该对话在后两轮重复输出实现原理和天气示例的现象一致。

OpenAI 官方 SDK 将 `ResponseOutputMessage` 列为合法的 `ResponseInputItem`，
其助手文字类型为 `ResponseOutputText` / `output_text`；将返回的输出消息作为下一轮输入是合法用法。
参见 [OpenAI Responses 类型定义](https://github.com/openai/openai-node/blob/master/src/resources/responses/responses.ts)。

## 与缓存和续聊的关系

- 请求处理顺序是先转换协议，再选择账号和缓存；缓存收到的历史已经缺少助手答案。
- `GeminiCacheManager.prepare()` 用缓存资源替代精确匹配的前缀，并发送剩余后缀；它不把旧答案拼入响应。
- 缓存索引校验模型、账号、调用方范围、系统指令、工具及完整消息前缀。
- `AccountScheduler` 保存会话归属和账号关联；生成请求的消息仍来自当前请求体。
- 关闭缓存无法恢复转换阶段丢掉的助手文字。修复后的历史能正确保留答案，旧缓存中不匹配的前缀会被跳过；仍匹配的短前缀可以继续使用。
- Git 历史显示，该文本处理代码来自 `fcac4c3`（最初添加 Responses API 支持），早于本分支的缓存修改。

## 本次修复与验证

在 Responses 普通消息转换中增加 `output_text`，保持助手消息的 `model` 角色及原消息顺序。

新增四项回归测试，覆盖：

1. 非流式输出作为下一轮输入，连续三轮答案完整保留。
2. 流式输出作为下一轮输入，连续三轮答案完整保留。
3. 工具调用前后的助手文字及旧文本格式完整保留，历史文字不进入系统指令。
4. 缓存关闭、命中续聊及修复前生成的缓存条目，均不丢失或重复助手答案。

前三项测试在修复前全部失败，修复后通过。`npm test`：346 项全部通过。

## 使正在使用的服务生效

修复随 `P.19` 发布。若只修改本地源码，Codex 连接的远程服务不会自动读取这些修改。

1. 将这份修复纳入实际服务的构建。源码运行时重启 Node 服务；Docker 部署时重建并更新容器。
2. 确认 Codex 使用的 Gemini 路由指向更新后的服务。若前面还有聚合网关，应确认实际后端也已更新。
3. 新开一段对话验证多轮续聊，避免旧的重复答案继续影响新回答。
4. 可依次询问“生成一个随机的八位字母数字代号，只回复代号”“你上一次回答的代号是什么？只回复代号”“再次原样写出这个代号”。
   三次答案应一致。代号由助手生成，用户消息不包含其具体值；同时检查实际发送的 Gemini `contents` 中存在对应的 `model` 文本消息。

缓存可以保持开启。本次修复无需修改环境知识、Codex 全局指令或清空全部历史。
